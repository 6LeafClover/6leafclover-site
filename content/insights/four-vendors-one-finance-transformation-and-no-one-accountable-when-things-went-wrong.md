## The setup

Gardens Gate Financial Services had assembled a strong team of specialist vendors for a finance automation programme: one handling core platform implementation, one handling data migration, one handling integration middleware, and one handling reporting and analytics. Individually, each was competent and well-regarded.

Collectively, they had a problem nobody had designed for. Each vendor was contracted separately, reported progress independently and had no formal obligation to the others. When an integration issue emerged — as it inevitably does when four separate systems need to talk to each other — each vendor could point, entirely reasonably from their own contract's perspective, to someone else's scope.

## Why this happens

This isn't usually a failure of vendor selection. It's a structural gap. No individual vendor is contracted, or incentivised, to own the space between contracts. Someone above all four needs to hold that space, and if nobody explicitly does, it simply goes unmanaged.

## What we built

- **One integrated delivery plan**, replacing four separate vendor plans that had previously been reconciled, imperfectly, after the fact
- **A single shared risk and issue log**, visible to all four vendors, so a risk raised by one couldn't quietly sit unaddressed because it looked like someone else's problem
- **A weekly governance forum** with all four vendors present simultaneously, chaired by a single accountable programme lead with the authority to make integration decisions on the spot

## The result

Issues that had previously taken three to four weeks to resolve — because they required back-and-forth between vendors who never spoke to each other directly — began resolving within days. The simple act of sitting all four vendors in the same room, answerable to the same person, removed the ambiguity that had let problems drift.

## The lesson

Multi-vendor automation programmes rarely fail because any single vendor is doing bad work. They fail because the space between vendors — where integration issues actually live — belongs to nobody by default. A single point of accountability above the contracts is what makes multi-vendor delivery actually deliver.
